Task 1 · Predict and explain · 6 points

At slope 2 and bias 1: 3 hours gives 7 credits; 5 hours gives 11; 0 hours gives 1. Show substitution into prediction = slope × hours + bias.

The slope adds 2 credits per extra hour; the bias adds a constant 1-credit offset. Changing the slope to 3 at 3 hours gives 3 × 3 + 1 = 10. The zero-hour output is a model calculation; zero lies outside the 1–4-hour training examples and does not independently establish actual fee policy.

3 points: three correct predictions. 2: parameter meanings and units. 1: changed-slope calculation plus the zero-hour limitation. Award partial credit for clear arithmetic with a minor slip.

Probe: “If only the bias rises by 2, which predictions change?” All model predictions rise by 2.

Task 2 · Repair the code · 6 points

hours = 3
slope = 2
bias = 1
prediction = slope * hours + bias
print(prediction)

The corrected code prints 7. "slope" is a string, while slope reads a numeric variable. Python repeats the string when multiplying by 3, then raises TypeError when adding the integer bias. It is valid syntax with an invalid type combination at runtime.

After fixing the calculation, print("prediction") still prints the literal word rather than the computed number. Removing those quotes reads the stored value. The two bugs have different effects; the first prevents the original print line from being reached.

2 points: both code fixes. 2: numeric variable versus string explanation. 2: distinguish the runtime type error from the wrong literal output and state the corrected result.

Probe: “What does "3" * 2 do?” It repeats the string into "33"; it does not produce numeric 6.

Negative signed errors indicate predictions below the actual target. The target stays fixed. Absolute and squared errors measure size differently; averaging signed errors would allow cancellation in a mixed-sign case.

Task 6 · Investigate failures · 6 points

Oversized rate: rate 0.5 requests 50 updates, but the provided guard accepts 5 updates and stops before accepting a proposed loss above 1012. The warning asks for reset and a smaller rate. The candidate has diverged; its huge parameters are not evidence of useful learning.

Changed prices: training and validation follow y=2x+1, while the later test follows y=3x+1. At 500 updates/rate0.03, training MAE is about 0.001071, but test MAE is about 7.495117 credits. At 7 hours the model predicts15.004348 against22; at8 it predicts17.005419 against25.

The update rule fitted the old relationship successfully; the later policy changed. Investigate source/date, price policy, input availability, and data coverage. Improve the system as appropriate, then use suitable fresh held-out data for a new independent evaluation. Repeated test-informed tuning does not restore independence.

2 points: warning evidence and learning-rate remedy. 2: training/test evidence for the shifted case. 2: distinguish optimisation from shift and propose a sound follow-up.

Probe: “Would adding 500 more updates on unchanged old data necessarily fix the new policy?” No; the old examples do not teach the changed relationship.

Task 7 · Design a new task · 4 points

Accept a coherent numeric prediction task with an input available at prediction time, a numeric target, units, two clearly synthetic example pairs, a training-fitted baseline, a meaningful split plan, and a changed-case explanation.

Example: input = registered attendees known before a class event; target = actual attendance count. Synthetic pairs: registered20 → attended16; registered30 → attended24. A simple baseline might use historical mean attendance from training events. Chronological validation and later test events suit a future-attendance claim. A changed venue or attendance policy could alter the relationship.

A good design may need more than one input. It does not have to prove a straight line is the best model. A yes/no target is classification and should be revised if the student claims to be designing this numeric-regression task.

1 point: task/input/target/units. 1: two labelled synthetic pairs. 1: baseline and split reasoning. 1: changed case and corresponding program/data review.
